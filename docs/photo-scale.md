# Диаметр по эталону на фотографии

`lib/photo-scale.ts` — автономная функция `estimatePhotoCircle(input)` без DOM, сети и зависимостей. Она переводит окружность по трём вручную выбранным вершинам зубьев из пикселей в миллиметры по известному отрезку. Масштаб нельзя получить из силуэта или из предполагаемого числа зубьев.

## Ввод и результат

```ts
const result = estimatePhotoCircle({
  imageWidth: 1600,
  imageHeight: 1600,
  referencePoints: [{ x: 300, y: 1250 }, { x: 800, y: 1250 }],
  referenceLengthMm: 100,
  referenceToleranceMm: 0.1,  // симметричная граница ±0,1 мм; опционально
  tipPoints: [{ x: 1100, y: 800 }, { x: 800, y: 1100 }, { x: 500, y: 800 }],
  pixelUncertaintyPx: 2,     // радиус ошибки каждой точки; по умолчанию 1
  confirmedCoplanar: true,
  confirmedAxialView: true,
});
// status: missing | rejected | ready
// diameterMm: 120 — только при ready
// circle: { center: {x:800,y:800}, radiusPx:300, diameterPx:600 }
// scaleMmPerPixel: 0.2
// uncertainty: { kind:'conditional_pixel_bound', pixelUncertaintyPx,
//   lowerDiameterMm, upperDiameterMm, maxRelativeDeviation,
//   includesReferenceTolerance }
// issues: {code,field,message}[]; warnings: string[]; missingFields: string[]
```

`referencePoints` содержит 0–2 точки, `tipPoints` — 0–3. Начало координат — левый верхний угол рабочего изображения; допустим непрерывный диапазон `[0,width] × [0,height]`. CSS-размер, увеличение экрана и координаты страницы сюда не передаются. Незавершённая разметка и неподтверждённые условия дают `missing`; недопустимый ввод или плохая геометрия — `rejected`. У них нет применимого `diameterMm`. Промежуточная `circle` может присутствовать для наложения контура на изображение.

Отсутствующий допуск эталона не трактуется как проверенный нулевой допуск: `includesReferenceTolerance=false` и отдельное предупреждение. Явный ноль разрешён как пользовательское условие, но сам по себе не доказывает отсутствие ошибки эталона. Аналогично `pixelUncertaintyPx=0` означает явно заданную идеальную геометрию, а не измеренную точность.

## Геометрия и условные границы

Пусть `a,b,c` — три стороны треугольника точек, `u=P2−P1`, `v=P3−P1`, `A=|u×v|`, `s` — длина эталона в пикселях, `L` — известная длина в мм. Диаметр описанной окружности:

```text
Dpx = abc / A
Dmm = Dpx · L / s
```

Центр считается в системе координат, перенесённой в первую точку и нормированной максимальной стороной треугольника. Это уменьшает потерю точности от больших абсолютных координат.

Предположение для интервала: истинная позиция **каждой из пяти точек** находится в евклидовом диске радиуса `ε` вокруг выбранной позиции. Это радиус в плоскости изображения, а не отдельная граница ±ε для каждой координаты и не стандартное отклонение. Длина эталона лежит в `[L−t,L+t]`, если введён `t`.

Из неравенства треугольника каждая сторона изменяется не больше чем на `2ε`. Для удвоенной площади:

```text
|Δ(u×v)| ≤ |u|·|Δv| + |v|·|Δu| + |Δu|·|Δv|
          ≤ 2ε(|u|+|v|) + 4ε² = B
```

Эта оценка применима при выборе любой из трёх точек за начало; берётся наименьшая из трёх доказанных верхних границ `B`. Поэтому, при положительных знаменателях:

```text
Dpx_low  = max(a−2ε,0) · max(b−2ε,0) · max(c−2ε,0) / (A+B)
Dpx_high = (a+2ε)(b+2ε)(c+2ε) / (A−B)

Dmm_low  = Dpx_low  · (L−t)/(s+2ε)
Dmm_high = Dpx_high · (L+t)/(s−2ε)
```

В реализации исходные длины и площадь также обрамлены интервальными операциями с округлением наружу до соседних IEEE-754 double; квадратный корень обрамляется соседними double. Это аналитическая консервативная граница для указанной модели ошибок, не перебор нескольких возмущений, не доверительный интервал 95% и не оценка вероятности.

`maxRelativeDeviation` — максимум отклонений двух границ от номинального диаметра, делённый на номинальный диаметр. Если знаменатель может обратиться в ноль, интервал не выпускается. При отклонении более 20% измерение блокируется. Такой порог — ограничение удобства и устойчивости метода, не производственный допуск.

## Проверки разметки

- Эталон не короче 20 px и 20ε.
- Конечные положительные размеры кадра и эталона; конечная неотрицательная ошибка и допуск меньше длины эталона.
- Точки внутри кадра; три вершины не совпадают и не лежат почти на одной прямой.
- Кратчайшая дуга, содержащая три вершины, охватывает минимум 150°; соседние точки разделены минимум на 20°.
- Восстановленная окружность целиком в кадре.
- Подтверждены одна плоскость эталона с торцом и съёмка по оси.

Три точки всегда задают окружность. Этот факт не проверяет, что настоящая деталь круглая, что выбраны именно вершины или что зубья эвольвентные. Для внутреннего колеса измеряется окружность кромок, обращённых к центру, а не внешний обод. У прямой площадки вершины середина хорды лежит внутри окружности; нужно выбирать реальные края на окружности, не произвольный центр площадки.

## Интерфейс и происхождение данных

`PhotoScale.tsx` открывает отдельное окно до 980 px. При 1× снимок целиком вписывается в доступные ширину и высоту и не увеличивается выше натурального размера; 2×/4× позволяют точнее ставить точки с прокруткой. Есть этапы, отмена последней точки, полный сброс и клавиатурный прицел (стрелки / Shift / Enter).

`PhotoWizard` использует рабочий canvas до 2048 px по большей стороне, без повторного JPEG-сжатия. Его размеры записываются в измерение; исходное разрешение камеры не приписывается рабочей разметке. SVG имеет совпадающий с изображением `viewBox`. Каждый щелчок переводится через актуальный `getBoundingClientRect()`, поэтому изменение CSS-размера и zoom не меняет восстановленный физический размер.

Ошибка автоматически предлагается как 2 пикселя экрана, переведённые в рабочие пиксели в момент выбора каждой точки; используется наибольшее значение из пяти. Позднее увеличение изображения не улучшает точность уже поставленной точки. Пользователь может ввести свою обоснованную границу; подсказка прямо называет значение предположением. Размытость, неуверенный выбор края или большой указатель требуют большей границы.

Только кнопка **«Использовать диаметр»** при `ready` и отдельном подтверждении правильной окружности переносит `diameterMm` и метод `tip_circle` в основной мастер. Число зубьев, направление, профиль, угол, смещение и высота вершин сохраняют независимые подтверждения. Происхождение диаметра и метода — `measurement`, даже если для остальных данных выбран чертёж или подтверждение пользователя.

Третий аргумент `onApply` сохраняет `photoMeasurement`: входные точки, рабочие размеры, длину и допуск эталона, ε, подтверждения, целевую внешнюю/внутреннюю окружность, номинальный результат, условный интервал и ссылки на методические источники. `sourceImage` сохраняет имя файла, MIME-тип и размеры исходного декодированного изображения; эти метаданные не заменяют сам исходник и не удостоверяют его подлинность. Само изображение в этот объект не включается. Границы в интерфейсе округляются наружу до 0,001 мм; в объекте сохраняется полная числовая точность. Замена фото сбрасывает все ответы; смена семейства, ручное редактирование диаметра/метода и изменение разметки убирают старую привязку к фото. Неподходящий файл также завершает прежнее состояние загрузки и не получает устаревший результат параллельного декодирования.

## Проверки и ограничения

`tests/photo-scale.test.ts` проверяет независимые прямоугольный и равносторонний треугольники, перестановки точек, поворот, перенос, изменение разрешения, некорректные данные, короткий эталон, узкие дуги, обрезанный круг, вырожденный и слишком широкий интервал. В 1000 воспроизводимых независимых возмущениях пяти точек и длины эталона интервал содержит известный истинный диаметр. Это регрессия аналитической реализации, а не экспериментальная валидация камеры.

Реальная фотография [A LEGO Technic gear with 24 teeth](https://commons.wikimedia.org/wiki/File:A_LEGO_Technic_gear_with_24_teeth.jpg), Didaictor, 2024, CC BY-SA 4.0, отдельно проверена в задаче существующим `analyzeGearImage`. Получен `manual_required`, `toothCount=null`, `confidence=0`, с предупреждениями о неоднородном фоне, возможной обрезке, нескольких компонентах и асимметрии. Файл не публикуется с приложением. В источнике нет подтверждённого масштаба в миллиметрах; фото не используется как эталон точности размеров или успешного распознавания.

Дисторсия объектива, перспектива, разная высота эталона и торца, толщина кромки, повреждения, некруглость детали и неверный выбор контура **не включены** в пиксельный интервал. Подтверждения пользователя не являются автоматической проверкой этих условий. Способ задаёт масштаб плоского снимка; он не выполняет полную калибровку камеры и не подтверждает посадки, производственный допуск или пригодность детали.

Методические первоисточники, проверенные 27.09.2026:

- [MathWorks — Measuring Planar Objects with a Calibrated Camera](https://www.mathworks.com/help/vision/ug/measuring-planar-objects-with-a-calibrated-camera.html): эталон и объект в одной плоскости, устранение дисторсии и преобразование пикселей в мировые координаты.
- [MathWorks — What Is Camera Calibration?](https://www.mathworks.com/help/vision/ug/camera-calibration.html): параметры камеры и радиальная/тангенциальная дисторсия. Ссылки описывают полноценную калибровку; упрощённый коэффициент масштаба в этом приложении её не заменяет.
