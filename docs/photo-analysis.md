# Локальный анализ фотографии зубчатого колеса

`photo-analysis.ts` — автономный TypeScript без зависимостей, DOM и сети. Нужен `ImageData` из canvas или совместимый RGBA-массив. Модуль не отправляет изображение серверу и не имитирует вызов нейросети.

## API и интеграция

```ts
import { analyzeGearImage, deriveMeasuredSpurParameters } from './photo-analysis';

const result = analyzeGearImage(context.getImageData(0, 0, canvas.width, canvas.height));
// Показывать пользователю предложение, его основания и вопросы.
// Не переносить найденный z в окончательную модель без подтверждения.
result.toothCount;             // number | null
result.outsideDiameterPx;      // number | null, исходные пиксели; НЕ мм
result.candidateTypes;         // external_circular | internal_ring | linear_rack | undetermined
result.status;                 // proposal_requires_confirmation | manual_required
result.confidence;             // эвристическое качество сигнала, НЕ вероятность правильности
result.warnings;
result.expertQuestions;         // массив {id,label,reason,options?}
result.moduleMm;                // ВСЕГДА null

const dimensions = deriveMeasuredSpurParameters({
  toothCount: 24,
  outsideDiameterMm: 52,
  confirmedExternalSpur: true,
  confirmedStandardFullDepth: true,
  confirmedZeroProfileShift: true,
  confirmedTipCircleDiameter: true,
});
// {ok:true,moduleMm:2,pitchDiameterMm:48,formula:'m = da / (z + 2)',warnings:[...]}
// Если хотя бы одно подтверждение отсутствует: {ok:false,missing:[...]}
```

В UI подтверждения должны изначально быть сняты. `external_circular` нельзя автоматически трактовать как прямозубое эвольвентное колесо. Это только периодический наружный торцевой контур: он не исключает косозубое колесо, звёздочку, шлиц или произвольную деталь с регулярными выступами. Кольцо распознаётся по периодичности внутреннего контура и гладкой внешней границе. Для кольца `outsideDiameterPx` означает внешний диаметр тела кольца и не участвует в формуле внешнего прямозубого колеса. Линейная рейка — лишь кандидат, найденный по вытянутому силуэту с периодическими выступами с одной стороны; число зубьев и модуль ей не назначаются.

## Что действительно вычисляется

1. Изображение ограничивается размером до 512 px по большей стороне. Альфа-канал компонуется на белом фоне. Цвет фона оценивается по медиане рамки.
2. Вычисляется RGB-расстояние от фона, применяется порог Оцу с нижним ограничением, выделяется крупнейшая связная компонента.
3. Проверяется размер объекта, контраст, доля других объектов, ровность фона, обрезка рамкой и симметрия силуэта.
4. Строятся наружный и при наличии отверстия внутренний радиальные профили по 2048 направлениям. Высшая граница первого/последнего материала оценивается с шагом 0,5 px рабочего изображения.
5. После удаления медленных гармоник ищется частота повторения 6–160. Верхняя граница дополнительно ограничивается разрешением: не менее 8 px на окружной шаг. Проверяются доля спектральной энергии, превосходство над альтернативными частотами, автокорреляция и повторяемость высоты выступов.
6. Число зубьев предлагается только при прохождении проверок изображения и периодичности. Эллиптичность ловится и при повороте эллипса на 45°, когда ширина и высота bounding box совпадают.

Результат диаметра — оценка геометрии пиксельного силуэта, не калиброванное измерение. В тестах 350-пиксельный диаметр оценён как 350,5–351,5 px; это не заявленная точность на настоящих фотографиях.

## Экспертные вопросы

Модуль выдаёт вопросы о расположении зубьев/типе пары, подтверждении z, измеренном диаметре, направлении зубьев на виде сбоку, профиле и угле зацепления, высоте зуба и смещении профиля, ширине венца/отверстии/ступице/пазе, ответном колесе/межосевом расстоянии/зазоре и рабочих условиях/принтере.

Нужен торцевой снимок строго по оси, целиком, без перекрытия, на простом контрастном фоне. При нечётном числе зубьев обычное измерение штангенциркулем между доступными поверхностями может не равняться диаметру окружности вершин; требуется корректный метод измерения. Измеренный диаметр в миллиметрах вводится отдельно. Модуль не выводит физический масштаб из пикселей.

## Проверки

```sh
node work/photo-analysis/photo-analysis.test.ts
```

Проверено на Node 24.18.0 (нативное выполнение TypeScript). Результаты сохранены в `test-results.json`. Это исполнение тестов, не отдельный TypeScript typecheck.

- Подсчёт z = 8, 12, 20, 24, 40, 72; белая деталь на тёмном фоне; цветной фон; прозрачность.
- Внутреннее кольцо с 40 зубьями и горизонтальная рейка.
- Отказ от z для гладкого круга, наклонённых контуров, обрезки, малого/низкоконтрастного силуэта, одного отсутствующего зуба, сложного фона и нескольких крупных объектов.
- Пустое изображение и некорректный ввод.
- Размерная формула и блокировка каждого отсутствующего подтверждения; некорректные диаметры и z.

Проверки используют синтетические радиальные силуэты с плоскими вершинами/впадинами и наклонными переходами. Они проверяют выделение периодичности, а не правильность эвольвентного геометрического ядра. Датасет настоящих фотографий, статистическая точность классификации и калибровка confidence не проверялись.

## Ограничения и дальнейшая валидация

Фотографии металлических блестящих деталей, сильные тени, текстурный фон, ступицы, эксцентрические отверстия, повреждения, оптическая дисторсия и очень мелкие зубья могут привести к отказу или ошибочному кандидату. Пороговая сегментация намеренно ограничена простыми условиями. Слабое повреждение/наклон не обязательно будет обнаружено. Визуально регулярная не-зубчатая деталь может пройти детектор. Рейка поддержана только при ориентации вдоль осей кадра; другие варианты остаются неопределёнными. Червячные, конические, гипоидные и прочие пространственные профили этим алгоритмом не определяются.

Модуль не восстанавливает профиль зуба, ширину, угол давления, профильное смещение, нормальный/торцевой модуль, допуски и пригодность к нагруженной работе. Для автоматического восстановления этих данных нужны дополнительные измерения и отдельный проверенный процесс. Проверки печати, геометрической замкнутости STL и расчёт прочности относятся к другим модулям.

## Источники геометрических ограничений

- [KHK, Calculation of Gear Dimensions](https://khkgears.net/gear-knowledge/gear-technical-reference/calculation-gear-dimensions/) — для стандартного внешнего прямозубого колеса d = mz и da = d + 2m. Формула da/(z+2) не переносится автоматически на смещённые, внутренние или косозубые колёса. В поисковой выдаче формула подтверждена; прямое открытие страницы в исследовательском инструменте вернуло некорректно декодированный ответ.
- [MathWorks, What Is Camera Calibration?](https://www.mathworks.com/help/vision/ug/camera-calibration.html) — измерение физической геометрии связано с параметрами камеры, дисторсией и соответствием известных пространственных точек изображению.
- [MathWorks, Structure from Motion from Two Views](https://www.mathworks.com/help/vision/ug/structure-from-motion-from-two-views.html) — даже реконструкция по двум калиброванным видам имеет неизвестный масштаб; в примере масштаб задаётся объектом известного размера.

Это инженерная исследовательская заготовка для сайта; прошедшие синтетические тесты не подтверждают точность восстановления реальной детали по фото.
