# Локальный анализ фотографии зубчатого колеса

`photo-analysis.ts` — автономный TypeScript без зависимостей, DOM и сети. Нужен `ImageData` из canvas или совместимый RGBA-массив. Модуль не отправляет изображение серверу и не имитирует вызов нейросети.

## API и интеграция

```ts
import { analyzeGearImage, deriveMeasuredSpurParameters } from './photo-analysis';

const result = analyzeGearImage(context.getImageData(0, 0, canvas.width, canvas.height));
// Показывать пользователю предложение, его основания и вопросы.
// Не переносить найденный z в окончательную модель без подтверждения.
result.toothCount;             // number | null
result.outsideDiameterPx;      // number | null, исходные пиксели; НЕ мм
result.candidateTypes;         // external_circular | internal_ring | linear_rack | undetermined
result.status;                 // proposal_requires_confirmation | damage_hypothesis_requires_confirmation | manual_required
result.damageHypothesis;       // отдельная гипотеза полного z при локальном дефиците, иначе null
result.confidence;             // эвристическое качество сигнала, НЕ вероятность правильности
result.warnings;
result.expertQuestions;         // массив {id,label,reason,options?}
result.moduleMm;                // ВСЕГДА null

// Для интерфейса v0.2 используйте inferGearFromMeasurements из photo-inference.ts.
// deriveMeasuredSpurParameters остаётся legacy helper для частного случая.
```

В UI подтверждения должны изначально быть сняты. `external_circular` нельзя автоматически трактовать как прямозубое эвольвентное колесо. Это только периодический наружный торцевой контур: он не исключает косозубое колесо, звёздочку, шлиц или произвольную деталь с регулярными выступами. Кольцо распознаётся по периодичности внутреннего контура и гладкой внешней границе. Для кольца `outsideDiameterPx` означает внешний диаметр тела кольца и не участвует в формуле внешнего прямозубого колеса. Линейная рейка — лишь кандидат, найденный по вытянутому силуэту с периодическими выступами с одной стороны; число зубьев и модуль ей не назначаются.

## Что действительно вычисляется

1. Изображение ограничивается размером до 512 px по большей стороне. Альфа-канал компонуется на белом фоне. Цвет фона оценивается по медиане рамки.
2. Вычисляется RGB-расстояние от фона, применяется порог Оцу с нижним ограничением, выделяется крупнейшая связная компонента.
3. Проверяется размер объекта, контраст, доля других объектов, ровность фона, обрезка рамкой и симметрия силуэта.
4. Строятся наружный и при наличии отверстия внутренний радиальные профили по 2048 направлениям. Высшая граница первого/последнего материала оценивается с шагом 0,5 px рабочего изображения.
5. После удаления медленных гармоник ищется частота повторения 6–160. Верхняя граница дополнительно ограничивается разрешением: не менее 8 px на окружной шаг. Проверяются доля спектральной энергии, превосходство над альтернативными частотами, автокорреляция и повторяемость высоты выступов.
6. Строгое число зубьев предлагается только при прохождении проверок изображения и периодичности. Эллиптичность ловится и при повороте эллипса на 45°, когда ширина и высота bounding box совпадают.
7. В v0.4 отдельный анализ медианного шаблона может предложить гипотезу полного числа зубьев при локальном дефиците материала. Он запускается только после тех же общих проверок изображения; результат не записывается в `toothCount`. Условия и ограничения описаны ниже.

Результат диаметра — оценка геометрии пиксельного силуэта, не калиброванное измерение. В тестах 350-пиксельный диаметр оценён как 350,5–351,5 px; это не заявленная точность на настоящих фотографиях.

## Экспертные вопросы

Модуль выдаёт вопросы о расположении зубьев/типе пары, подтверждении z, измеренном диаметре, направлении зубьев на виде сбоку, профиле и угле зацепления, высоте зуба и смещении профиля, ширине венца/отверстии/ступице/пазе, ответном колесе/межосевом расстоянии/зазоре и рабочих условиях/принтере.

Нужен торцевой снимок строго по оси, целиком, без перекрытия, на простом контрастном фоне. При нечётном числе зубьев обычное измерение штангенциркулем между доступными поверхностями может не равняться диаметру окружности вершин; требуется корректный метод измерения. Измеренный диаметр в миллиметрах вводится отдельно. Анализатор не выводит физический масштаб из пикселей. Отдельный [инструмент масштаба v0.3](photo-scale.md) использует известный эталон, три вершины и самостоятельные подтверждения условий съёмки.

## Проверки

```sh
npm test
```

Проверено на Node 24.18.0 (нативное выполнение TypeScript). TypeScript отдельно проверяется командой `npm run check`.

- Подсчёт z = 8, 12, 20, 24, 40, 72; белая деталь на тёмном фоне; цветной фон; прозрачность.
- Внутреннее кольцо с 40 зубьями и горизонтальная рейка.
- Отказ от z и от гипотезы восстановления для гладкого круга, наклонённых контуров, обрезки, малого/низкоконтрастного силуэта, сложного фона и нескольких крупных объектов.
- Один отсутствующий зуб: строгий `toothCount=null`; отдельная проверяемая гипотеза вместо заполнения числа как факта.
- Пустое изображение и некорректный ввод.
- Размерная формула и блокировка каждого отсутствующего подтверждения; некорректные диаметры и z.

Проверки используют синтетические радиальные силуэты с плоскими вершинами/впадинами и наклонными переходами. Они проверяют выделение периодичности, а не правильность эвольвентного геометрического ядра. Датасет настоящих фотографий, статистическая точность классификации и калибровка confidence не проверялись.

## Ограничения и дальнейшая валидация

Фотографии металлических блестящих деталей, сильные тени, текстурный фон, ступицы, эксцентрические отверстия, повреждения, оптическая дисторсия и очень мелкие зубья могут привести к отказу или ошибочному кандидату. Пороговая сегментация намеренно ограничена простыми условиями. Слабое повреждение/наклон не обязательно будет обнаружено. Визуально регулярная не-зубчатая деталь может пройти детектор. Рейка поддержана только при ориентации вдоль осей кадра; другие варианты остаются неопределёнными. Червячные, конические, гипоидные и прочие пространственные профили этим алгоритмом не определяются.

Модуль не восстанавливает профиль зуба, ширину, угол давления, профильное смещение, нормальный/торцевой модуль, допуски и пригодность к нагруженной работе. Для автоматического восстановления этих данных нужны дополнительные измерения и отдельный проверенный процесс. Проверки печати, геометрической замкнутости STL и расчёт прочности относятся к другим модулям.

## Источники геометрических ограничений

- [KHK, Calculation of Gear Dimensions](https://khkgears.net/gear-knowledge/gear-technical-reference/calculation-gear-dimensions/) — для стандартного внешнего прямозубого колеса d = mz и da = d + 2m. Формула da/(z+2) не переносится автоматически на смещённые, внутренние или косозубые колёса. В поисковой выдаче формула подтверждена; прямое открытие страницы в исследовательском инструменте вернуло некорректно декодированный ответ.
- [MathWorks, What Is Camera Calibration?](https://www.mathworks.com/help/vision/ug/camera-calibration.html) — измерение физической геометрии связано с параметрами камеры, дисторсией и соответствием известных пространственных точек изображению.
- [MathWorks, Structure from Motion from Two Views](https://www.mathworks.com/help/vision/ug/structure-from-motion-from-two-views.html) — даже реконструкция по двум калиброванным видам имеет неизвестный масштаб; в примере масштаб задаётся объектом известного размера.

Это инженерная исследовательская заготовка для сайта; прошедшие синтетические тесты не подтверждают точность восстановления реальной детали по фото.

## Обратный расчёт v0.2

`inferGearFromMeasurements(input)` принимает только явно подтверждённые факты `{value, source}`. Источник — measurement, drawing или user_confirmation. Поддержаны spur, helical, herringbone, internal, internal-helical, rack, helical-rack. Силуэт предлагает гипотезы, но не подтверждает тип или эвольвентность.

- Наружные: mn = da / [z/cosβ + 2(1+x)].
- Внутренние: mn = da / [z/cosβ − 2(1−x)].
- Рейка: mn = pt·cosβ / π; pt измеряется вдоль перемещения.

Для круговых профилей отдельно требуются корректный диаметр окружности вершин, коэффициент смещения, ha*=1 и отсутствие укорочения вершин. Нечётное z не допускает необработанного размера между губками. Неизвестные α, β и x остаются вопросами; даже если модуль уже вычислен, полная модель не готова без оставшихся данных. Ширина и размеры тела вводятся отдельно, нулевой зазор/условная галтель остаются обозначенными предположениями модели.

Статусы: missing, rejected, ready. Возвращаются `missingQuestions`, `issues`, `hypotheses`, `calculation`, `provenance`; готовый patch параметров существует только при ready. Паспорт из UI сохраняет подтверждённые источники и формулу. После ручного изменения параметров привязка к фото очищается. Загрузка другой фотографии очищает все прежние измерения. Проверки включают эталоны KHK, 7 семейств, отсутствие скрытых значений по умолчанию, численные границы и происхождение данных.

## Локальное повреждение: отдельная гипотеза v0.4

```ts
result.status === 'damage_hypothesis_requires_confirmation';
result.toothCount === null; // утраченные зубья не наблюдались
const exampleHypothesis = {
  status: 'requires_independent_confirmation',
  method: 'robust-period-template-v1',
  toothCount: 24,                 // предполагаемое ПОЛНОЕ число
  boundary: 'outer',              // outer | inner
  supportedTeeth: 21,             // ожидаемые ячейки, совпавшие с шаблоном
  visibleToothFraction: 21 / 24,  // доля таких ячеек, не вероятность
  candidatePitchDeg: 15,
  pitchScatterFraction: 0.005,    // пример; RMS шага / ожидаемый шаг
  templateErrorFraction: 0.03,    // пример; RMS формы / высота шаблона
  damagedSectors: [{
    startDeg: 75, endDeg: 120, wrapsZero: false,
    estimatedToothCells: 3,
    evidence: 'Локальный дефицит контура относительно медианного шаблона…',
  }],
  evidence: ['…'],
};
```

Числа в примере API иллюстративные. `supportedTeeth` — число **ожидаемых зубцовых ячеек**, согласующихся с одним шаблоном. Это не точный подсчёт физически целых зубьев. Сектор может включать частично затронутые соседние ячейки; `estimatedToothCells` нельзя трактовать как установленное число сломанных зубьев.

Алгоритм использует дополнительные проверки, а не сниженные пороги прежнего строгого анализатора:

1. Неизменённые общие gates: весь объект в кадре, ровный фон, достаточный контраст и размер, доминирование одного компонента, допустимые отношение сторон, эллиптичность и смещение центра масс. Отказ любого из них запрещает и новую гипотезу. Например, доля основного компонента должна быть больше 85%; меньшие посторонние частицы этим условием не исключаются автоматически.
2. До шести сильнейших спектральных частот предлагают возможный полный период. Каждая проверяется заново по отдельным зубцовым ячейкам; сам спектральный максимум числом зубьев не становится.
3. Радиальный профиль складывается по кандидатному периоду в 40 фазовых позиций на ячейку. Медианный шаблон строится по всем ячейкам, поэтому локальный дефицит не задаёт форму большинства.
4. По наименее отклоняющимся 70% краевых значений оценивается медленная первая гармоника радиуса. Если пропавшая вершина сдвинула центр bounding box, допускается одно уточнение центра менее чем на 4% среднего радиуса. Радиальные лучи затем геометрически пересэмплируются; просто вычесть синусоиду из радиуса недостаточно, поскольку неверный центр также искажает фазу. Перенос допустим только для контура, сохраняющего однозначную угловую параметризацию. Это не коррекция наклона камеры и не обход исходного circular gate.
5. Шаблон должен иметь один выраженный выступ на период; удвоенные/кратные периоды с несколькими выступами отклоняются. Сохранная ячейка имеет RMS расхождения не более 16% высоты шаблона и сопоставимую высоту. Независимо проверяются расстояния между центрами сохранных выступов: RMS относительного разброса шага не более 6%, отдельное отклонение не более 15%.
6. Не менее 75% ячеек и минимум шесть ячеек должны согласоваться с шаблоном. Допускается не больше четырёх отклоняющихся ячеек в не больше чем трёх секторах: срез трёх зубьев может затронуть часть соседней ячейки. Несогласованные участки должны давать преимущественно **отрицательный** остаток относительно шаблона. Средний дефицит — минимум 8% высоты, положительный остаток — максимум 4% и не более трети дефицита. Произвольные и положительные искажения не заполняются.
7. Несколько прошедших разных периодов остаются неопределённостью. Гипотеза выдаётся только для одного периода. У внутреннего колеса анализируется направленный внутрь материальный выступ при гладкой наружной границе кольца.

Ветка проверяется и тогда, когда старый спектральный критерий ещё допускал число: небольшой локальный дефект не должен получать метаданные неповреждённого контура. Пороги — ограничения исследовательского метода, не технические допуски и не статистическая гарантия. Алгоритм не меняет исходные пиксели и не дорисовывает утраченные зубья.

### Подтверждение в мастере и паспорт

Карточка показывает **возможное полное число**, долю согласующихся ячеек, разброс шага и расхождение формы. Кнопка «Подставить гипотезу» переносит число в поле и всегда снимает подтверждение, даже если оно было отмечено ранее. Профиль, тип, угол, смещение, диаметр и размеры тела по-прежнему требуют самостоятельных исходных данных. Перечень фото-типов — whitelist семи поддержанных `InferredGearKind`; новые ручные семейства не включаются автоматически.

Опция «Показать участки для проверки» накладывает угловые сектора на локальный снимок без изменения его пропорций. Координаты берутся из `centerPx` в рабочем изображении; 0° направлен вправо, положительное направление — по часовой стрелке. Это ячейки для осмотра, **не измеренные границы трещины или разрушения**.

Паспорт получает `photoAnalysisEvidence`: алгоритм, статус, `strictToothCandidate=null`, отдельную гипотезу и её аргументы, диагностику, имя/тип/размер оригинала, размеры рабочего изображения, центр, пиксельный наружный диаметр и систему координат. Поля `hypothesisTransfer.transferred` и `independentlyConfirmedByUser` разделяют явный перенос гипотезы и последующее подтверждение полного числа пользователем. Примечание происхождения `toothCount` также описывает эту последовательность. Ручное изменение поля числа зубьев удаляет отметку переноса и снимает подтверждение; новая фотография сбрасывает все ответы. После ручного изменения построенной модели связь с фото очищается общим механизмом приложения. Измерение диаметра по эталону v0.3 сохраняется отдельно в `photoMeasurement`.

### Что проверено, а что не проверено

`tests/photo-damage.test.ts` содержит независимые аналитические формы: косинусные, трапецеидальные и треугольные выступы; z = 12, 24, 37, 60; разные угловые фазы и утрату одного–трёх соседних выступов. В матрице из 36 повреждённых контуров получены 30 правильных гипотез и шесть консервативных отказов, без ошибочного z. Отказы на некоторых положениях повреждения связаны с большим сдвигом центра bounding box или исходной асимметрией; пороги не ослаблены ради полного охвата. Дополнительно проверены три раздельных дефекта, сектор через 0°, потеря фрагмента тела, внутренние зубья и сохранение строгого пути для целого контура.

Отрицательные синтетические случаи: неравномерные шаги и высоты, смесь частот, гладкий круг с пятном или выемкой, половина колеса, большая доля отсутствующих выступов, тень, перспектива/эллипс с поворотом, обрезка кадром, низкий контраст, сложный фон и заметный отдельный объект. Во всех этих проверенных случаях — `manual_required`, обе оценки числа отсутствуют.

Отдельный независимый прогон использовал растеризованные эвольвентные профили с генерированными корневыми переходами: z = 24, 32, 47, 60; радиус вершин на снимке 100/180 px; три фазы; потеря 0/1/2/3 угловых участков. В 96 случаях: 24/24 целых профиля сохранили правильный строгий кандидат, 72/72 повреждённых дали правильную отдельную гипотезу, ошибочных z не получено. Это **синтетическая регрессия**, а не измеренная точность на настоящих фотографиях и не независимая проверка геометрического ядра.

Обязательный реальный отрицательный контроль: [A LEGO Technic gear with 24 teeth](https://commons.wikimedia.org/wiki/File:A_LEGO_Technic_gear_with_24_teeth.jpg), Didaictor, 2024, CC BY-SA 4.0, 923 × 923 px. В повторном прогоне v0.4: `manual_required`, `toothCount=null`, `damageHypothesis=null`; предупреждения о контакте выделенного контура с рамкой, неоднородном фоне, нескольких компонентах и асимметрии.
