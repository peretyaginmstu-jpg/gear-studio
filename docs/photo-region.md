# Область детали для анализа фото · v0.10

«Указать деталь на фото» позволяет исключить из анализа эталон или соседний предмет. Полный рабочий снимок сохраняется для PhotoScale, просмотра повреждений и происхождения. Это необязательная операция внутри существующего фото-пути, без нового обязательного шага.

## Пользовательский путь

Кнопка доступна рядом с загрузкой и на шаге «Тип и зубья», включая отказ анализа. В окне показывается полный снимок. Пользователь отмечает два противоположных угла рамки; порядок углов не важен. Должна помещаться вся деталь с запасом однотонного фона. Эталон может находиться снаружи.

Доступны касание/щелчок, стрелки для перемещения прицела, Shift для шага 10 px, Enter/пробел для постановки угла и четыре числовых поля. Небольшое движение указателя при прокрутке не считается точкой. Рамка и затенение относятся только к выбранной области анализа, изображение не растягивается. Координаты задаются в пикселях рабочего снимка, а не CSS-пикселях экрана.

Редактирование рамки локально до «Применить область». «Отмена», Escape и закрытие окна сохраняют принятую область и ответы. «Анализировать весь снимок» явно возвращает полный кадр. Скрытая ветка закрывает окно через `useActivePopup`; при возвращении оно не раскрывается само.

Применение **другой** области означает возможную другую деталь: снимок модели, подтверждение и оформление аннулируются. Сбрасываются фото-семейство и его опрос, z и подтверждение, профиль, углы/смещение, диаметр/шаг, общая нормаль, размеры тела, принятый долбяк, PhotoScale и все его локальные точки. Явный `analysisRevision` входит в ключи family/span/PhotoScale, поэтому прежние незавершённые ответы не появляются вновь. Полный снимок остаётся прежним.

Неизменённая рамка — no-op. Прямоугольник ровно по полному кадру эквивалентен режиму полного снимка. Повторное применение не стирает измерения и не запускает лишний анализ. Новая загрузка сбрасывает область и ответы; общий request token исключает применение запоздавшего результата предыдущего файла/области.

Предложенное z остаётся неподтверждённым. Гипотеза утраченных зубьев переносится только отдельно, как раньше. Область не выбирает семейство, профиль, модуль или масштаб.

## Чистый API

`lib/photo-region.ts` не зависит от DOM, canvas, React или внешних пакетов:

```ts
interface PhotoRegion { x: number; y: number; width: number; height: number }
analyzeGearRegion(image: ImageDataLike, selected?: PhotoRegion | null): RegionAnalysis
normalizePhotoRegion(region: PhotoRegion | null, size: WorkingImageSize): PhotoRegion | null
photoRegionFromCorners(first: RegionPoint, second: RegionPoint, size: WorkingImageSize): PhotoRegion | null
samePhotoRegion(a: PhotoRegion | null, b: PhotoRegion | null, size: WorkingImageSize): boolean
```

Размеры полного рабочего изображения — положительные целые числа, не более 2048 по каждой стороне и 2048² пикселей. Это соответствует предобработке загрузки PhotoWizard; исходный файл может иметь больше пикселей и сохраняет свои размеры в `sourceImage`.

RGBA должен содержать ровно `width × height × 4` целых байтов 0…255. Для обычного `ArrayLike<number>` проверяются также невыбранные пиксели; `Uint8Array` и `Uint8ClampedArray` уже ограничены байтами. Размер проверяется до чтения/копирования массива. Невалидные, дробные, бесконечные, отрицательные, нулевые и выходящие за кадр рамки вызывают ошибку. API не обрезает неправильные координаты до допустимого диапазона.

Прямоугольник использует границы пиксельных ячеек, полуоткрытые интервалы `[x, x + width) × [y, y + height)`. Два угла в обратном порядке нормализуются отдельной функцией; отрицательная ширина в самом API анализа не допускается.

## Анализ и координаты

Для `null` или полного прямоугольника вызывается тот же `analyzeGearImage` с прежним входом: результат точно совпадает с прежним анализом. Для области копируются только выбранные целые RGBA-пиксели. Crop не растягивается, не интерполируется и не переводится в новый физический масштаб. Штатный детектор сам уменьшает выбранный вход до максимальной стороны 512 px, со своей прежней сеткой выборки и округлением размеров.

Из локального результата меняется только центр:

```text
centerFull.x = centerCrop.x + region.x
centerFull.y = centerCrop.y + region.y
```

Диаметр уже выражен штатным детектором в пикселях его входа, то есть рабочего crop. При простом вырезании пиксельный размер не меняется, поэтому дополнительного множителя для диаметра нет. Углы повреждённых секторов не поворачиваются и не масштабируются. DamagePreview получает переведённый центр и исходное полное изображение. Пиксельный диаметр анализа остаётся оценкой контура; он не заменяет измерение по трём вершинам и эталону.

Проверки детектора не ослаблены: край crop становится краем проверяемого кадра; обрезание, неоднородный фон, низкий контраст, конкурирующие компоненты, перспектива, недостаточное разрешение и нарушения периодичности продолжают проверяться. Выбор области не исправляет наклон камеры и не доказывает, что пользователь действительно включил всю деталь.

PhotoScale получает полный рабочий снимок и его полные размеры. Точки эталона за областью анализа остаются допустимыми. Анализ контура и физическое измерение используют одну полную рабочую систему координат, но имеют разные ограничения и подтверждения.

## Происхождение

`RegionAnalysis` возвращает `analysis: PhotoAnalysis` и `evidence: PhotoRegionEvidence`. В паспорте и задании печати последнее находится по пути:

```text
evidence.photoAnalysisEvidence.analysisRegion
```

Запись имеет схему `zatseplenie.photo-region.v1` и поля:

- `method`: `full-image` или `user-selection`;
- `region`: фактический прямоугольник, включая полный прямоугольник для полного кадра;
- `workingImage`: полные размеры рабочего снимка;
- `processedImage`: фактические размеры после штатного уменьшения детектором;
- `processedToWorking`: сдвиг x/y и коэффициенты масштаба по двум осям, включая округление размеров детектора;
- `coordinateSystem`: `working_image_pixels; origin=top-left; angle=clockwise-from-right`;
- `regionConvention`: `integer-pixel-cell-edges; half-open`;
- `cropOperation`: `integer-pixel-copy; no-stretch`.

Прежние `centerPx`, `outsideDiameterPx`, `workingImage` и повреждённые сектора в `photoAnalysisEvidence` теперь явно относятся к полному рабочему кадру. Исходный файл и его размеры сохраняются отдельно. Новый элемент не заменяет familySelection, PhotoScale, общую нормаль или независимое подтверждение повреждённых зубьев.

Версия приложения — 0.10.0; внешние схемы паспорта и задания остаются v6. ROI — происхождение выбора области, не оценка точности измерения или автоматическое подтверждение модели. Оплата и отправка заказа не добавлены. Проверки и их фактический статус: [QA области фото](photo-region-qa.md).
