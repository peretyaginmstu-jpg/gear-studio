# Предпроверка внешней циклоидальной пары · v0.13

`analyzeGearPair({ first, second, centerDistanceMm? })` выделяет два
`kind: 'cycloidal'` в отдельную ветку `external_cycloidal`. Это пара внешних
цилиндрических прямозубых колёс, **не** эксцентриковый циклоидальный редуктор,
цевочное зацепление или смешанная эвольвентная пара. Одиночное математическое
ядро и его система высот `ha=m`, `hf=1.25m` не изменены.

## Какие окружности должны совпадать

Для сопряжённых аналитических боковин одна производящая окружность образует
эпициклоиду головки первого колеса и гипоциклоиду ножки второго. Обратная пара
«головка второго / ножка первого» должна иметь свою общую окружность. Эти
**два** радиуса в общем случае могут различаться. В нашем одиночном ядре
`cycloidRollingRadius` один для обеих частей каждого зуба; поэтому реализован
только частный случай, где `r₁=r₂=r`. Другое значение не означает, что любая
циклоидальная система невозможна: оно несовместимо с этой парой заданных
однокружных профилей.

Этот конструктивный принцип и дуга производящей окружности как путь
номинального контакта описаны в первоисточнике:
[R. J. Durley, Kinematics of Machines, 1907, §67, печатные с. 197–199](https://ecommons.cornell.edu/server/api/core/bitstreams/f7252185-b02b-4ebb-aa6f-2027d7839795/content).
[Библиографическая запись Cornell](https://ecommons.cornell.edu/entities/publication/0722c053-1ce6-4027-b910-76ce03e8a55f)
указывает автора, год и издание J. Wiley & Sons. Ниже приведены собственные
выводы для конечных ветвей конкретного ядра, а не перенесённая из книги
сертификация наших зубьев. Параметрические координаты сверены с
[Epicycloid](https://mathworld.wolfram.com/Epicycloid.html) и
[Hypocycloid](https://mathworld.wolfram.com/Hypocycloid.html), Wolfram MathWorld.

## Номинальная кинематика и конечные боковины

Обозначения: `Rᵢ=mzᵢ/2`, `p=πm`, `a₀=R₁+R₂`; общая система координат
`O₁=(0,0)`, `O₂=(a₀,0)`, полюс `P=(R₁,0)`. Оси параллельны `+Z`. Для
канонической комплексной записи боковин:

```text
Eᵢ(t) = (Rᵢ+r) exp(it) − r exp(i(Rᵢ+r)t/r)
Hᵢ(t) = (Rᵢ−r) exp(it) + r exp(−i(Rᵢ−r)t/r)
```

При положительном делительном перемещении `s` правая головка первого и
правая ножка второго, после противоположных вращений `s/R₁` и `−s/R₂`,
дают одну точку `C₊=(R₁+r(1−cosγ), r sinγ)`, где `γ=s/r`. Обратные части
при `s<0` дают `C₋=(R₁−r(1−cosγ), −r sinγ)`, `γ=−s/r`. Утонение каждого
зуба входит в постоянный фазовый поворот его правой боковины. Это позволяет
согласовать **одну** выбранную сторону, но не доказывает зазор противоположной
стороны, отсутствие пересечения полного контура или реальную фазу сборки.
Дифференцирование даёт общую нормаль через `P`, а нормальные компоненты
скоростей совпадают при `ω₂/ω₁=−R₁/R₂`.

Крайние параметры `t_ai`, `t_fi` берутся из фактического аналитического
профиля. Для первых ветвей `0≤γ≤π`:

```text
Γ_ai = Rᵢ t_ai / r; Γ_fi = Rᵢ t_fi / r
Γ₁₂ = min(Γ_a1, Γ_f2); Γ₂₁ = min(Γ_a2, Γ_f1)
Smax = r(Γ₁₂ + Γ₂₁)
nominalFlankCoverageUpperBound = Smax / (πm)
```

`Smax` — верхняя граница делительного перемещения, доступного конечным
аналитическим боковинам. Если она меньше одного шага, боковин недостаточно
для непрерывной передачи в этой номинальной кинематике: результат `fail`.
Величина не меньше 1 даёт только `warning`. Это **не контактное отношение ε**:
реальное пересечение тел, фаза и контакт полных контуров не решены. Численная
полоса `±1e−9` около 1 обозначается `at-boundary`; это вычислительный допуск,
не производственный запас.

Например, две отдельно построимые модели `z=6, m=1, r=0.87, j=0, bore=0`
дают границу `0.8919008209950929 < 1`. Этот отказ основан на конечных
боковинах и не объявляет физически невозможными другие системы зубьев.

## Проверки и неизвестные

Для каждой детали вызываются `buildCycloidalMesh` с `flankSamples: 6` и
`validateMesh`. Сохраняются исходные ограничения на радиус, достижимость
впадины, непересечение локального профиля, толщину, отверстие, ширину,
дискретизацию и ресурсы. Плотность проверочной сетки не является пакетом
экспорта или классом точности. Затем сравниваются модуль/круговой шаг,
производящие радиусы и введённое `a` с `a₀`. Для равенства используется
`|u−v|≤1e−9 max(1,|u|,|v|)` — только численный критерий.

Неноминальное `a` отвергается как выход за область этой предпроверки, без
эвольвентного рабочего угла. Постоянный угол давления здесь неприменим и
не сравнивается. `profileShift` и `helixAngleDeg` должны быть нулевыми,
как требует одиночное ядро. Необходимые радиальные промежутки по окружностям
`a−ra₁−rf₂` и `a−ra₂−rf₁` не заменяют проверку столкновения боковин.
Общая ширина `min(b₁,b₂)` вычисляется при **условном** совпадении средних
плоскостей; реальное осевое положение не введено.

Даже при согласовании всех условий:

- `fullPairConjugacyVerified: false`;
- `idealAssembly.actualMountingVerified: false`, `toothPhaseRad: null`;
- `contactRatio`, `backlashMm`, `interferenceFree`: `null`;
- прочность, ресурс, допуски изготовления и печатные условия не проверены.

## API, JSON и интерфейс

Схема отчёта остаётся `zatseplenie.pair-analysis.v3`. Новые добавочные поля:
`report.cycloidalModels` — две компактные нормализованные модели, размеры и
проверки сеток без массивов вершин; `report.cycloidalGeometry` — величины
номинальной пары, пределы обеих ветвей и явно условная сборка. Для старых
режимов они равны `[]` и `null`. Все старые эвольвентные `report.dimensions`
для циклоидальной ветки равны `null`; её отношение `z₂/z₁` имеет собственное
поле. Смешанные семейства возвращают `unsupported`.

Ошибка построения, несовпадение `m/r/a` дают `cycloidalGeometry: null`.
При согласованной номинальной геометрии, но недостаточном покрытии шага,
границы **сохраняются** вместе с `fail`: это количественная причина отказа,
а не показатели подтверждённой рабочей пары. Вычисленная геометрия не
добавляется в паспорт одиночного STL.

`input.centerMode` равен `nominal-reference-circles` без введённого расстояния
или `user-specified-for-nominal-precheck` с ним. Прежние режимы экспорта
остаются прежними. Обе входные модели копируются в независимый снимок.

Диалог фиксирует первую готовую модель; ответная первоначально имеет
удвоенное число зубьев (не более 250), тот же модуль и фактический общий `r`.
Это редактируемый пример, не распознанная деталь. Доступны `z₂,m₂,r₂`, ширина,
отверстие, утонение и необязательное фактическое `a`. Постоянный `α`, смещение
и наклон скрыты. Ошибка не подгоняет первую модель и не меняет введённые
параметры. Кнопка сохраняет реальный локальный JSON с обеими деталями и
ограничениями. Фото, ручной путь, STL и условия подтверждения не меняются.
